# Excel 工作簿使用与计算说明

[对账原型.xlsx](对账原型.xlsx) 提供模拟样本的明细计算、订单与客户汇总、核对页和三张原生透视表。本说明对应仓库中的成品，公式范围按当前 966 条明细、143 张订单和 100 条回款分配设置。

## 查看与更新结果

1. 打开工作簿，进入 `checklist` 查看金额和数据质量指标。
2. 在 `checklist!B4` 设置回款截止日，默认值为 `2026-10-06`。订单和客户的已收、余额随公式重新计算。
3. 在 `calc_customers` 查看客户月账，在 `calc_orders` 查看订单明细汇总。
4. 在 `native_pivots` 查看客户、商品和日期透视表；修改源数据后，在 Excel 中执行“数据 → 全部刷新”。

`checklist` 的 C 列是保存时的独立参考值，其中截止日已收和未结清对应 `2026-10-06`。更换 B4 后，C 列不会自动切换到另一个截止日；应使用 `data/expected/customer_summary.csv` 中对应日期的核对值，或重新运行 Python 与 SQL 核对。

| 截止日 | 净应收（元） | 已收（元） | 未结清（元） | 截止日外回款条数 |
| --- | ---: | ---: | ---: | ---: |
| 2026-09-30 | 44,914.30 | 6,000.00 | 38,914.30 | 84 |
| 2026-10-06 | 44,914.30 | 26,254.15 | 18,660.15 | 0 |

截止日只控制回款到账时间，包含当日。订单范围固定为输入中的 9 月订单。

## 工作表结构

| 工作表 | 用途 |
| --- | --- |
| `checklist` | 回款截止日、金额核对、口径排除与暂缓订单计数 |
| `calc_customers` | 6 家客户的订单数、净应收、已收、余额和结清状态 |
| `calc_orders` | 143 张订单的汇总、阻断明细计数与整单暂缓状态 |
| `calc_lines` | 966 条明细的引用、金额计算和异常检查 |
| `pivot_report` | 按客户、商品和日期的公式交叉汇总 |
| `native_pivots` | 三张可刷新的原生透视表 |
| `exceptions` | 当前样本的异常说明；不是自动刷新的异常记录列表 |
| `raw_order_lines` | 原始订单明细 |
| `dim_products`、`dim_customers` | 商品与客户维度 |
| `fact_receipts`、`fact_payments` | 整笔收款与订单分配 |

原始表保留源数据，计算表通过公式引用。商品和客户查找使用 `INDEX/MATCH` 精确匹配；出现未匹配编号时保留公式错误，便于定位输入问题。

## 明细计算：`calc_lines`

A—L 列引用订单源数据，M—O 列补充商品名称、规格和客户名称，P—R 列计算交付金额、退货金额与净应收，S—W 列记录异常及处理状态。

以下为成品第 2 行的金额公式，向下覆盖至第 967 行：

| 列 | 字段 | 公式 |
| --- | --- | --- |
| P | `gross_amount` | `=INT((ROUND(raw_order_lines!H2*10,0)*ROUND(raw_order_lines!J2*100,0)+5)/10)/100` |
| Q | `return_amount` | `=INT((ROUND(raw_order_lines!I2*10,0)*ROUND(raw_order_lines!J2*100,0)+5)/10)/100` |
| R | `net_amount` | `=$P2-$Q2` |

H 列为实际交付数量，I 列为签收退货数量，J 列为成交单价。数量和单价先分别转换为整数，交付与退货金额分别取整到分后再相减。取整顺序与 Python 和 SQL 保持一致，详见 [金额计算与交叉核对](../docs/calculation-notes.md)。

| 检查列 | 成品中的检查内容 |
| --- | --- |
| S：`quantity_exception` | 下单量非正、退货量大于交付量、交付量大于下单量 |
| T：`unit_exception` | 明细计价单位与商品表不一致 |
| U：`price_exception` | 成交单价超出商品模拟价格区间 |
| V：`duplicate_key` | `order_id + line_no` 重复 |
| W：`data_quality_status` | 数量、单位或重复主键问题标为“阻断”；单价越界标为“提示” |

合理少送和退货按实际数量计费。当前正式样本没有数据质量问题，净应收合计应为 **44,914.30 元**。

## 订单汇总：`calc_orders`

每行一个订单。先汇总明细净应收，再按订单编号和截止日汇总回款，避免连接两张明细表时重复累计金额。

| 列 | 字段 | 第 2 行公式或含义 |
| --- | --- | --- |
| A—D | 编号、客户与日期 | 订单列表及精确查找 |
| E | `line_count` | `=COUNTIF(calc_lines!$A$2:$A$967,$A2)` |
| F | `blocked_line_count` | `=COUNTIFS(calc_lines!$A$2:$A$967,$A2,calc_lines!$W$2:$W$967,"阻断")` |
| G | `net_receivable` | `=IF($F2>0,"",ROUND(SUMIF(calc_lines!$A$2:$A$967,$A2,calc_lines!$R$2:$R$967),2))` |
| H | `received` | `=IF($F2>0,"",ROUND(SUMIFS(fact_payments!$D$2:$D$101,fact_payments!$B$2:$B$101,$A2,fact_payments!$C$2:$C$101,"<="&checklist!$B$4),2))` |
| I | `balance` | `=IF($F2>0,"",$G2-$H2)` |
| J | `status` | `=IF($F2>0,"暂缓",IF($I2=0,"已结清","未结清"))` |

存在阻断明细的订单显示“暂缓”，G—I 列留空；客户汇总排除这些订单。单价风险提示保留供人工复核。

`receipts` 和 `payments` 是同一笔钱的两个视角。订单已收只汇总分配表，不与整笔流水金额相加。

## 客户汇总与透视表

`calc_customers` 按客户汇总订单数、净应收、已收和余额，使用 `calc_orders!J` 排除暂缓订单。`pivot_report` 提供公式交叉汇总，`native_pivots` 使用 `calc_lines` 作为源数据。

| 透视视图 | 用途 |
| --- | --- |
| 客户 | 核对客户净应收与交付金额 |
| 商品 | 查看商品交付、退货数量及计价单位 |
| 日期 | 查看每日订单明细的配送情况 |

不同商品的数量可能以公斤、袋或桶计量，跨商品比较时应保留单位。透视表基于明细数据，不自动应用订单层的暂缓规则；有阻断数据时，以订单和客户公式汇总及 Python 对账输出为准。

## 重新导入与异常检查

五张原始 CSV 位于 `data/raw/`。通过 Excel“数据 → 从文本/CSV”导入，选择 UTF-8 编码，将客户、商品、订单及流水编号设为文本，日期和数值列按实际类型导入。

| 原始工作表 | CSV 文件 | 行数（不含表头） |
| --- | --- | ---: |
| `raw_order_lines` | `order_lines.csv` | 966 |
| `dim_products` | `products.csv` | 20 |
| `dim_customers` | `customers.csv` | 6 |
| `fact_payments` | `payments.csv` | 100 |
| `fact_receipts` | `receipts.csv` | 7 |

更换数据时，需同步更新固定公式范围、订单编号列表、独立参考值和透视表源范围。新增原始行不会自动扩展全部计算范围。

Excel 工作簿用于当前样本的金额核对，检查规则不覆盖 Python 程序的全部输入校验。需要完整异常清单时，在项目根目录运行：

```bash
python src/reconcile.py --cutoff 2026-10-06 --out outputs
python sql/verify_sqlite.py --cutoff 2026-10-06
python -m unittest discover -s tests -v
```

Python 回归测试使用 `tests/fixtures/dirty/` 检查重复主键、非法数量和未知商品。验证 Excel 的检查列时使用工作簿副本，在现有范围内制造单位不一致或数量关系错误，核对阻断标记与整单暂缓状态，避免修改正式快照。
