# 金额计算与交叉核对

## 统一计算顺序

每条明细先计算交付金额和退货金额，分别四舍五入到人民币分，再相减得到净应收。随后汇总到订单级，关联截至对账日的回款，最后汇总到客户级。

```text
交付金额   = ROUND_HALF_UP(实际交付数量 × 成交单价, 0.01)
退货金额   = ROUND_HALF_UP(签收退货数量 × 成交单价, 0.01)
明细净应收 = 交付金额 - 退货金额
订单净应收 = 同一订单的明细净应收之和
订单余额   = 订单净应收 - 截止日内有效回款
```

交付金额与退货金额分别取整，与先相减再取整可能相差一分。因此各实现遵循相同计算顺序，并保留两项金额供逐行核对。

## 各实现的精度处理

| 实现 | 计算方式 | 核对范围 |
| --- | --- | --- |
| Python | 从文本读取为 `Decimal`，使用 `ROUND_HALF_UP` 取整到分 | 正式快照和回归测试中的异常样本 |
| SQLite SQL | 数量、单价保留原始文本，转为整数后计算金额分值 | 正式快照的两个回款截止日 |
| Excel | 数量乘 10、单价乘 100 后分别取整，以整数乘积计算金额 | 已提交模拟快照的公式与汇总 |
| 独立样本检查 | 不引用生成器函数，从 CSV 重读后用整数重算 | 全部订单、客户、流水及两个截止日 |

当前样本数量固定为一位小数、单价和回款金额固定为两位小数。SQL 的 `REPLACE(x, '.', '')` 换算依赖这一固定格式：`'4.1'` 转为 `41`，`'4.60'` 转为 `460`。它不适用于任意小数位数的外部输入。

在当前非负数量和单价范围内，交付金额的整数分值计算为：

```text
交付金额（分）= (数量十分位整数 × 单价分整数 + 5) 整数除以 10
```

退货金额使用相同规则，再用两个整数分值相减。Excel 单元格和透视表的底层数值仍可能存在二进制浮点尾数；金额核对按人民币分精度比较，不把底层浮点数逐位相等作为判断标准。

## SQLite 的类型与比较

SQLite 验证脚本将数量、单价、价格区间和金额列声明为 `TEXT`，以保留输入的小数位数。若使用数值亲和性，`'2.30'` 可能变为 `2.3`，再去掉小数点会得到 `23`，破坏原本的分值换算。

数量和价格区间比较先显式换算成整数，避免直接进行文本比较。例如文本 `'9.6'` 与 `'10.1'` 的字符顺序不代表数值大小。

`sql/verify_sqlite.py` 为 SQLite 改写视图创建语句和截止日参数。自动化检查验证的是 SQLite 执行结果；MySQL 建表脚本属于目标环境参考，迁移时仍需检查查询语法、类型转换和取整规则。

## 汇总与回款核对

一张订单可以包含多条商品明细，也可以对应多条回款分配。直接连接两张明细表会重复累计金额，因此先各自汇总到“一行一个订单”，再关联应收与已收。

`receipts.csv` 记录整笔到账，`payments.csv` 记录到账款向订单的分配。同一流水的分配合计应等于流水金额，两张表的已收总额分别核对，不相加。

对账截止日控制回款到账时间，包含当日。订单范围由输入文件决定。当前样本只含 9 月订单，不涉及期初余额或跨期退货。

## 核对方法

1. 运行独立样本检查，确认快照记录数、文件校验值和金额。
2. 运行 Python 回归测试，检查正常样本、阻断订单和金额取整。
3. 在两个截止日分别运行 Python 对账及 SQLite 查询，与 `data/expected/` 比较。
4. 在 Excel 中检查明细、订单、客户汇总及抽样订单；更换截止日时使用对应的外部核对值。
