# 生鲜批发订单与对账

面向生鲜批发配送月结场景的数据处理项目，将订单明细、实际交付、签收退货和回款分配汇总为可追溯的订单账单与客户对账表。项目提供 Python 对账程序、Excel 工作簿和 SQL 核对查询，展示从原始数据校验到结果交叉核对的完整流程。

仓库使用固定随机种子生成的模拟数据，客户名称、业务编号和记录均带模拟标识，不包含真实客户或交易信息。

## 项目概览

| 项目 | 内容 |
| --- | --- |
| 业务期间 | 2026-09-01 至 2026-09-30 |
| 数据规模 | 6 家客户、20 种商品、143 张订单、966 条明细 |
| 回款记录 | 7 笔收款流水、100 条订单分配记录 |
| 输出结果 | 订单对账表、客户汇总表、异常与口径排除清单 |
| 实现方式 | Python 标准库、Excel 公式与透视表、SQLite SQL 核对 |
| 校验方式 | 独立样本检查、Python 回归测试、两个截止日的 SQL 核对 |

项目处理按实际交付计费、按成交价冲减退货、一笔回款分配到多张订单、部分付款及跨月回款等情况。原始 CSV 保留不变，结果可按订单编号追溯到商品明细和收款流水。

## 快速开始

### 运行 Python 对账

需要 Python 3.10+，无需安装第三方包。获取仓库后运行对账：

```bash
git clone https://github.com/Titus-code/fresh-order-reconciliation.git
cd fresh-order-reconciliation

python src/reconcile.py --cutoff 2026-10-06 --out outputs
```

程序读取 `data/raw/`，生成三份 UTF-8 BOM 编码的 CSV：

| 文件 | 内容 |
| --- | --- |
| `order_reconciliation_20261006.csv` | 每张有效订单的应收、已收、余额及结清状态 |
| `customer_reconciliation_20261006.csv` | 按客户汇总订单数和金额 |
| `exceptions_20261006.csv` | 数据质量问题、风险提示与截止日口径排除记录 |

使用其他输入目录或复现月末结果：

```bash
python src/reconcile.py --input-dir data/raw --cutoff 2026-09-30 --out outputs
```

`--cutoff` 控制回款的到账截止日，包含当日；订单范围由输入数据决定。本样本的订单范围固定为 2026 年 9 月。

### 查看 Excel 工作簿

下载 [对账原型.xlsx](excel/对账原型.xlsx)，打开 `checklist` 查看核对指标，打开 `calc_customers` 查看客户结果。`checklist!B4` 是可编辑的回款截止日，`native_pivots` 中包含三张可在 Excel 中刷新的原生透视表。

工作表结构、公式、更新步骤和核对范围见 [Excel 工作簿使用与计算说明](excel/Excel原型分步指南.md)。

### 执行校验

```bash
python scripts/check_sample_data.py
python -m unittest discover -s tests -v
python sql/verify_sqlite.py --cutoff 2026-09-30
python sql/verify_sqlite.py --cutoff 2026-10-06
```

GitHub Actions 执行上述检查，并运行两个截止日的 Python 对账。SQL 自动化校验使用 SQLite；`sql/schema.sql` 提供 MySQL 8.0 建表参考，当前检查不包含 MySQL 服务上的执行验证。

## 计算规则

| 规则 | 处理方式 |
| --- | --- |
| 交付计费 | 按实际交付数量乘以成交单价 |
| 退货冲减 | 按该条明细成交时的单价计算 |
| 明细净应收 | 交付金额和退货金额分别四舍五入到分，再相减 |
| 订单余额 | 订单净应收减去截止日内有效回款 |
| 回款核对 | `receipts` 为整笔到账，`payments` 为订单分配；分别汇总核对，不叠加 |
| 关联顺序 | 订单明细和回款分配各自汇总到订单级，再按订单号关联 |

Python 使用 `Decimal` 和 `ROUND_HALF_UP`；SQL 核对使用整数分运算；Excel 先将样本数量和单价规范化为整数，再按相同顺序取整。具体实现与输入精度要求见 [金额计算与交叉核对](docs/calculation-notes.md)。

## 校验与异常处理

Python 对账程序检查主键、客户与商品关联、单位、数量关系、价格区间及回款关联。存在阻断明细异常的订单整单暂缓，避免将不完整订单作为可确认账单输出；价格区间越界保留为风险提示。

异常清单包含来源文件、行号、业务编号、类型、说明、分类和是否阻断。截止日之后的回款归为“口径排除”，不计入当次已收金额：

| 截止日 | 数据质量问题 | 口径排除记录 |
| --- | ---: | ---: |
| 2026-09-30 | 0 | 84 |
| 2026-10-06 | 0 | 0 |

正式样本覆盖 50 条少送明细、27 条签收退货明细，两类可能重叠。合理少送和退货属于正常业务变化。重复主键、非法数量、未知商品等异常使用 `tests/fixtures/dirty/` 单独验证；Excel 和 SQL 的核对范围以当前模拟快照为主。

如需重新生成样本，使用新目录保存，生成器拒绝覆盖已有快照：

```bash
python scripts/generate_sample_data.py --output-dir data-rebuilt
```

项目范围为订单与回款对账，不包含库存管理、采购结算、税务开票、路线优化或多用户权限。当前输入中的回款分配已预先确认；接入实际业务时，需要确认分配规则、历史余额和跨期退货口径。
